# Documentation Writer

When asked to write documentation:

1. Understand the audience (developer, user, or both).
2. Start with a short overview of what the thing does.
3. Explain how to use it with real examples.
4. Cover important parameters, return values, or options.
5. Note any limitations or gotchas.

## Style

- Use simple language
- Prefer examples over long explanations
- Use headings and bullet points for scanability
- Keep it accurate — do not invent behavior
